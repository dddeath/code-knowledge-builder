# 维护真实性与人类输出内容门

维护结果反映本次读取的快照与人类页面，不再以旧可读性报告的通过状态代替检查。首页与阅读指南优先给出任务、结果和阅读入口；完整命令、测试总数与日志保留在机器证据中。

## 维护结果如何解释

- 固定源码快照缺失、版本漂移，以及人类与兼容镜像不一致，属于交付失败。独立检查继续执行，同一份机器报告同时保留快照和内容发现。
- 工作树新增提交会单独报告事实过期。历史快照仍成立时，维护不把新版 HEAD 当作快照损坏，也不阻断只读检索。
- 新代码页、导航和新提交记录正文违反内容门时，报告具体页面与行号。空泛模式表示需要重新核对职责，不表示已经证明该实体的语义错误。
- 尚未升级的历史正文保留原文，不因缺少 V3 元数据而伪造已审阅状态。历史职责的空泛模式保留为待审阅警告；新版生成器写入的内容门标记使新代码页继续接受严格检查。

旧 Graphify 关系报告仅有一项精确的兼容例外：原“围绕任务继续缩小范围”章节中固定的三条查询示例列为警告。该例外依赖原章节与命令的完整文本，并不豁免整份报告；相同命令进入代码页、首页、阅读指南、记录导览或新记录时仍会触发内容门。

## 记录入口覆盖范围

普通新建、历史追加和替换都会在写入正文前检查完整命令、完整测试计数、特定空泛说明及缺少阅读目的的链接。少量技术实体、功能覆盖、性能摘要和明确边界仍可保留。

不带作者包的普通正文保留旧格式兼容，元数据明确记为“历史格式、已做内容检查”，不代表完整 V3 章节通过。自动会话等现有调用方仍属于这一兼容路径。

显式 V3 作者包保留可重放的章节上下文。记录入口重新验证正文、合同版本、章节证据和所引用文件，而不是信任包内已有的通过状态。作者包只渲染人类摘要；章节证据与完整日志引用留在机器元数据。完整标题不重复包装，也不在既有 V3 章节后自动增添来源目录。

V3 记录的修改使用完整作者包替换；不隐式退回旧正文格式，也不把无章节上下文的追加伪装成整页通过。维护重新读取实际记录、作者包与证据，识别章节缺失、正文漂移及证据变化。

作者包及其证据目录需要继续保留。普通记录与迁移系统原有的外部证据保存方式未在本批扩展；移动或删除记录所引用的作者包会使维护报告证据缺失。

## 关系说明的边界

仅有词法候选来源的关系保留为“待核验的词法关联”，不直接写成调用或依赖，也不用于推导已确认的测试覆盖。已有明确调用来源仍可保留调用叙述。完整候选与来源继续保存在机器图中，不通过删除人类页面代替关系判断。

## 尚未覆盖的合同

这批修复不是完整 V3 迁移。机器报告明确保留未全覆盖状态：自动会话调用方、历史普通记录、代码职责页的完整章节预算，以及旧 Graphify 查询示例仍有各自的兼容边界。旧笔记与来源审阅内容不被批量改写，源码事实也不随本批修改自动同步。

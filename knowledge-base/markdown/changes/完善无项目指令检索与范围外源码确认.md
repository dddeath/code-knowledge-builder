# 完善无项目指令检索与范围外源码确认

标签：#类型/变更

## 修改内容

项目补齐了没有自动注入项目指令时的 CKB 检索契约。Harness 已精确加载 Skill 时，可以从显式任务绑定、管理身份或项目登记中确定知识库，随后执行 `brief`、打开阅读包并继续窄范围读取；没有 Skill 应用证据时，不会把普通对话标记为已使用 CKB。

检索结果还新增范围外源码确认。问题明确指出一个固定 Git 中存在、但当前知识库尚未展开的唯一源码中心时，Agent 会说明缺少的范围并询问人类是否追加；确认后复用既有 `scope extend`，暂不追加时仍可继续窄读源码。

## 修改时间

2026 年 9 月 4 日完成开发、管理复查与源码合并。

## 修改原因

此前检索顺序主要依赖项目级 `AGENTS.md`，部分 Harness 没有自动注入该文件时，Skill 中缺少完整的项目绑定与调用说明。另一方面，检索没有覆盖问题中的明确源码路径时，只能返回继续读源码，无法区分普通漏检与知识库范围不足。

## 修改方式

实现保留现有 SQLite 检索、事实新鲜度和追加中心流程，只增加两个关键连接：

- Skill 与 Harness manifest 分别说明项目指令、Skill 加载、会话激活、OUTPUT 发现和 CLI fallback 的来源；
- 检索完成后使用 `catalog.json`、`scope.json`、固定 Git blob 和唯一 selector 生成确认建议。

warning 按候选范围判断。其他语言或其他路径的局部 warning 原样保留，不阻塞扩库建议；只有 warning 明确影响候选并禁止缺失推断时，才保留诊断而不提出扩库。

## 涉及的其他特性

该修改与会话级 stdio、管理 Agent、Agent Policy、源码事实新鲜度、关键词慢路径和既有 `scope extend` 相连。它没有改变检索排序，也没有建立第二套扩库、cutover 或 rollback。

## 验证结果

隔离探针验证了没有项目指令时的 Skill 未加载与精确加载两条路径，包括 `brief`、阅读包、反馈、研究缺口、窄源码读取、新鲜度、stdio 和 CLI fallback。范围外确认验证了 CLI、`brief` 与 stdio 使用同一结果，覆盖范围内漏检、歧义路径、来源不足、stale、服务失败、重复询问和相关／无关 warning。三项合并后的完整回归执行 377 项测试，376 项通过，1 项因可选 NumPy 依赖跳过。

## 当前边界

确认建议只处理问题中显式出现的仓库相对源码路径或完整 entry。路径必须在固定 Git catalog 中唯一解析，并且知识库事实为 current；建议本身不会扫描仓库、重建知识库或自动执行扩库。各 Harness 的静态契约已经统一，宿主是否真实加载仍以对应运行事件或真实会话证据为准。

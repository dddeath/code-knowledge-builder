# 将 Obsidian Canvas 原型纳入实验发布

标签：#类型/变更

## 修改内容

本次发布把当前 Obsidian Canvas 原型作为实验功能随源码和 lite 包提供。Agent 可以从一次固定的 CKB 检索结果中选择少量知识页、工作记录和源码入口，在隔离 staging 中生成 Canvas、validation manifest 和 rollback manifest。

实验功能不会替代知识库首页、工作记录或机器图谱，也不会改写稳定知识页。README 提供面向人类的稳定提示词，用户试用后可以反馈入口速度、缺失或多余节点、错误跳转和回滚体验。

## 修改时间

2026 年 9 月 2 日确认以实验状态进入 GitHub 发布。

## 修改原因

纯 Markdown 能稳定保存结论和来源，但跨页面关系仍需要人类逐个跳转。Canvas 可能降低理解当前问题所需的跳转次数；在正式纳入 Skill 前，需要先让真实用户试用并获得导航反馈。

## 修改方式

实验发布保留三个关键边界：

- 只从本次检索包中选择有限节点和关系，不展开完整机器图谱；
- 生成前验证请求、路径和预算，写入后重开 Canvas 与两个 manifest；
- 所有写入位于明确 staging，失败不提升，成功结果可以按清单回滚。

## 涉及的其他特性

该功能依赖 CKB brief 检索、知识页回链、源码打开入口和 Obsidian JSON Canvas 文件。它作为独立原型随核心源码发布，不接管现有 Obsidian companion plugin，也不依赖通用 Obsidian MCP。

## 验证结果

原型专项测试 35 项通过，固定样例生成 4 个节点和 3 条边，路径泄漏为 0；确定性输出、事务写入、失败恢复、回滚和冻结 benchmark 合同均已验证。最终发布还会从 GitHub 新克隆副本重新运行源码、知识库与 LFS 校验。

## 当前边界

实验状态只确认生成与回滚合同，不确认真实人类导航收益。用户反馈和后续人类会话将决定节点预算、默认关系、提示词和是否进入正式 Skill；在此之前不把 Canvas 描述为稳定核心能力。

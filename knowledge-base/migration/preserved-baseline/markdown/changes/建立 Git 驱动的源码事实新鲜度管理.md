# 建立 Git 驱动的源码事实新鲜度管理

标签：#类型/变更

## 修改内容

知识库现在会比较固定源码提交、Git 当前提交与工作树状态，并在 Agent 检索前给出事实是否仍然有效的确定性结论。已合并代码尚未同步时，旧事实会被标记为过期，不再作为当前确定性答案。

## 修改时间

2026 年 9 月 3 日。

## 修改原因

源码持续提交、合并或拉取后，稳定知识库仍可能固定在旧提交。若检索流程不检查这一差异，Agent 会把历史实现误当成当前实现；若直接自动覆盖稳定库，又会失去人工审阅、回滚和并发安全边界。

## 修改方式

系统建立了六种固定状态，分别表示当前、存在未提交覆盖层、已提交事实过期、Git 暂不可用、等待迁移和 staging 已具备切换条件。提交、分支切换、合并与拉取事件都会触发检查；迁移计划只创建可审阅计划，不直接覆盖稳定库。状态锁采用所有者标识和文件身份复核，并对 Windows 文件占用实施有界重试。

## 关联影响

这项修改连接 Git 事件、会话自动化、紧凑检索、协作记录和稳定知识库迁移。工作树中的临时修改只形成可丢弃覆盖层；只有固定提交、审阅、索引、镜像和维护证据完整时，staging 才能进入切换准备状态。

## 已验证结果

固定测试已覆盖提交、分支切换、合并、拉取、脏工作树、Git 暂不可用、迁移证据不足、陈旧检索保护和并发锁。Windows 锁文件被短暂占用时会在限定时间内重试；锁所有者已经变化时不会删除他人的锁。

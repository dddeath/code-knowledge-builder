# 真实语义向量检索三臂对照实验

标签：#类型/实验

## 实验问题

真实中文语义向量检索或与当前 SQLite 检索融合，是否能在固定代码定位问题上提高排序质量，并把索引、延迟、内存和进程成本控制在预设上限内。

## 固定范围

实验固定十二个中文代码定位问题、同一份 `bd85195…` 知识语料、前八条结果、一次冷启动和五次热查询。三组分别为当前 SQLite 检索、真实本地语义向量检索和固定倒数排名融合。模型固定为 `Qdrant/bge-small-zh-v1.5` 的指定 revision，测量期间禁止网络访问。

## 实验方法

本地 FastEmbed 与 ONNX Runtime 为 `1937` 个源码实体生成 `512` 维归一化向量，并在隔离副本上执行精确余弦排序。每题每组保存命中、排名、分数、缺失原因、上下文估算、冷热延迟、内存和子进程；独立脚本从 `216` 行原始记录重算质量与聚合结果。

## 实验结果

当前 SQLite 的 Recall@8、MRR@8、nDCG@8 为 `0.750`、`0.611111`、`0.646822`。纯向量组为 `0.583333`、`0.294444`、`0.364928`，三项均回退；融合组 Recall@8 提高到 `0.833333`，但 MRR@8 和 nDCG@8 降至 `0.588294`、`0.645929`，未满足“至少一项提高且其余不回退”的固定规则。首次索引约 `145.6` 秒，单实体增量约 `22.7` 毫秒，索引约 `4.90` MB；模型与隔离运行时合计约 `265.2` MB。纯向量热查询中位数约 `11.1` 毫秒，但完整过程峰值内存约 `1.32` GB，额外子进程峰值 `3` 超过上限 `1`。

## 如何解释

真实模型已经成功运行，但当前向量文本、查询指令和融合方式没有形成无回退的质量收益。较低的纯向量热延迟不能抵消质量回退和完整资源门失败，因此没有路线进入生产实验，默认检索保持不变。

## 适用边界

结论只适用于这十二个问题、当前实体文本合同、固定模型与本机测量。实验实现使用 FastEmbed/Qdrant 模型，不等同于 QMD；它也没有修改生产检索、默认排序或稳定知识库调用方式。

## 下一步

QMD 仍需在同一问题集和资源上限下单独验证。后续若调整实体文本、查询表示或候选融合，必须重新冻结协议并重新测量，不能沿用本次结果推断增益。

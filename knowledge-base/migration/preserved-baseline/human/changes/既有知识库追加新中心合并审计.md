## 已确认行为

- 旧 entries 与新增 entries 形成 append-only 确定性并集；新增中心必须唯一解析到同一固定 Git snapshot 中受支持、已跟踪的非文件实体。重复、已存在、零解析、多解析、不支持语言、未跟踪路径、重叠或已占用 staging 均有固定失败分类。
- 未变化文件按 Git blob 与 passed parse 精确复用；未变化且分类形状兼容的实体复用旧 review。新增实体、分类受影响实体和新增关系端点进入 delta review；audit 会重新计算集合，不信任 start 保存的计划。
- audit 只有在 append-only、delta、可变层保留、review、全局审计、双 SQLite、human/markdown 镜像、简体中文、来源、readability、reference、research gap、operation journal、Agent Protocol 和 maintain 全部通过后才标记 ready。
- cutover 在同卷目录中核对旧 OUTPUT 全树与 repository commit，先原子改名保存备份，再提升 staging；失败时反向恢复。rollback 核对当前新树、旧备份和双 SQLite 后恢复旧 OUTPUT。
- 隔离 fixture 实际保留 46 条工作记录、1 个已审阅 reference、3 个 open research gap 和两份学习笔记 human/markdown 原文，并证明旧中心和新中心都进入 `machine/knowledge.sqlite`。

## 管理审计发现并关闭的问题

初版在同一固定 snapshot 连续执行两次 cutover 后留下两条 `cutover-complete` 控制记录，`status` 和 `rollback` 无法确定当前链顶。管理探针实际复现 `expected one active cutover control record, found 2`，因此没有直接合并。

修复后，当前 active 操作由当前 OUTPUT 的完整树清单唯一匹配；控制记录保存父操作和链深度。第二次 rollback 精确恢复第一次 cutover 的树并重新激活父操作，继续 rollback 可恢复根状态；重复 active、历史控制漂移和第二次 cutover 中途失败均有负例，历史审计记录不会被删除。管理探针已重新运行并通过。

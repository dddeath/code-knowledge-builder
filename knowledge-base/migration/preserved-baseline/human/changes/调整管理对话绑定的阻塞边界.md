# 调整管理对话绑定的阻塞边界

标签：#类型/变更

## 修改内容

管理对话现在可以在 integration worktree 存在未提交修改时先完成身份绑定。绑定结果会明确报告工作树并非干净以及有限的变更路径；开发任务派发、合并和稳定知识库同步仍保持原有阻断条件。

## 修改时间

2026 年 9 月 3 日。

## 修改原因

对话绑定只负责登记 Harness、仓库、知识库、integration branch 和绑定提交，并不创建分支、改写源码或执行合并。把“工作树必须干净”放在绑定入口，会让正在阅读或修改代码的 Agent 失去管理身份；真正需要干净工作树的是后续任务派发和集成动作。

## 修改方式

绑定预检继续核对 workspace、仓库根、稳定知识库、当前分支和 HEAD，但将工作树状态作为结果返回。绑定后的实时状态仍会把未提交修改列为阻断项，因此 Agent 可以恢复管理上下文，却不能借此绕过派发与合并前提。

## 关联影响

这项修改影响 Codex 和其他 Harness 的管理对话登记、异常关闭后的任务恢复以及开发任务派发。仓库缺失、知识库缺失、分支不匹配和 HEAD 不存在仍会停止绑定；已经绑定的脏工作树仍不能创建开发任务。

## 已验证结果

回归测试确认了三组行为：脏工作树可以完成绑定并返回变更状态；同一绑定随后保持阻断，直至工作树恢复干净；缺失仓库、缺失知识库和错误分支继续失败。完整单元回归、真实语言提供器集成以及两套低版本批量迁移流程均保持通过。

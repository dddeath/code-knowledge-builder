# 增加受控的工作记录正文替换与回滚

标签：#类型/变更

## 修改内容

本次修改为既有工作记录增加受控正文替换能力。管理 Agent 可以按精确类型和标题替换当前正文，同时更新 human、markdown、记录元数据、RECORDS 导览、两个 SQLite 和 operation journal；普通新建与追加行为保持不变。

每次成功替换都会返回独立 rollback manifest 和可直接运行的回滚入口。回滚只恢复该次操作拥有的页面与索引状态，并在覆盖前检查替换后的对象是否发生外部漂移。

## 修改时间

2026 年 9 月 2 日完成开发、管理审计、合并和稳定知识库验证。

## 修改原因

原记录接口只有新建与追加。旧页面需要整体重写时，追加会同时保留旧正文和新正文，使人类无法判断当前有效内容；直接编辑生成页面又会绕过镜像、索引、来源和操作日志。

## 修改方式

实现由四个关键阶段组成：

- 精确定位同类型、同标题的受管记录，并冻结当前页面、元数据和索引摘要；
- 在操作专用 staging 中生成候选，验证镜像、记录导览和两个 SQLite 的目标逻辑状态；
- 按固定顺序提升页面、元数据、导览和索引，任一步失败都逆序恢复；
- 保存 owner-safe 锁、operation journal 和带漂移保护的回滚清单。

## 涉及的其他特性

该修改与人类页面模板、工作记录投影、Agent 索引、机器知识库、operation journal、维护门和多页面回滚顺序相连。它只替换已存在记录，不用于移动页面类型或模糊匹配标题。

## 验证结果

专项测试覆盖目标缺失、类型不符、无效正文、证据失败、候选镜像漂移、两个索引阶段的故障补偿、并发锁、回滚冲突和重复回滚。合并后的完整回归共 268 项，全部通过；真实 staging 还完成了一次旧页面替换、实际回滚和重新替换。

## 当前边界

多个页面连续替换时，它们会共享 RECORDS 等投影文件；若需要整体撤销，应按替换发生的逆序执行各自 manifest。检测到人类页面、投影或索引已经被后续操作修改时，旧 manifest 会报告冲突，不覆盖较新的结果。

## 第一部分：面试前速查

<a id="quick1"></a>
### 速查 1｜两条岗位路线与共同主线

**A：Agent 方向游戏测试。**第一种对象是游戏：Agent 负责提出操作和解释证据，测试判定仍需可核对的规则或状态。第二种对象是 Agent：评估它是否选对动作、遵守预算、准确发现问题并留下证据。游戏缺陷被正确发现时，游戏测试可能失败而 Agent 任务成功。

**B：Agent 应用开发。**围绕代码修改助手说明输入、工具接口、检索、长会话状态、失败恢复与验收。先讲小规模可运行流程，再讨论扩展。

**联合 30 秒介绍：**我围绕代码 Agent 的信息获取做了两个项目。CKB 把固定版本代码组织成可定位、可追溯的源码入口；DSH Layered Memory 将长会话历史按预算移出当前输入，需要时检索并回查。华为实习中，我承担组件仿真与仿真加速相关开发、门禁样例定位和修复。两个个人项目分别有检索或记忆评测，联合代码修改助手作为设计题训练。

两条路线都先学 C01-C18。A 接 A01-A08，重点练 EX01、EX05、EX06；B 接 B01-B08，重点练 EX02、EX04、EX05。基础薄弱时先看 C18，再回到对应项目。

每次复习输出：一段脱稿口述、一张状态图、一个边界样例。掌握等级用 0-3，含义见导航；“读过”只记学习记录。

### 速查 2｜CKB：说清入口、来源与结果

**问题：**Agent 理解陌生代码仓时，整仓读取昂贵，纯关键词又要求知道名字。

**本人工作：**设计并实现固定版本的代码索引与检索工具，组织语法/语义证据、来源与实体归属、SQLite 检索、预算输出及分析记录复用。Tree-sitter、LSP、SQLite 是集成组件。

**30 秒：**输入自然语言任务，工具返回文件、实体、源码行范围和职责说明。固定 Git 版本保证这些解释来自同一份代码；词法检索先找到种子，关系检索补充邻近文件，再在 token 预算内返回入口。

```text
固定 Git 版本：commit、blob、path、range
    -> Tree-sitter/LSP -> facts
    -> SQLite 实体/章节/关系索引
    -> FTS5 + 有界图检索 -> 预算化 Agent pack
    -> entity / neighbors / source 下钻
```

**必须记住：**Flask 3.1.3，24 个核心 Python 文件、10 个修改意图；文件 Recall@8 都为 100%，精确符号召回为 CKB 40%、grep 100%。上下文中位数 2,294 对 11,228 tokens；常驻中位延迟 24.9 对 73.2 ms，P95 47.6 对 86.3 ms。约 92.1 秒构建/复核/审计另计。

**追问入口：**版本切换 C02；解析冲突 C03；FTS5 与图 C05-C06；预算/缓存 C07；指标 C08。答文件定位成功后，接“用符号和源码下钻继续核查”，不要把它说成已测得更高修改成功率。

### 速查 3｜DSH：保存历史与当前可见分开

**问题：**历史和工具输出持续增长，窗口容量固定；纯摘要可能失去原始细节。

**30 秒：**插件把冷历史保存为可回查记录，在当前请求里先留下短引用，再按压力精简或移走引用。原文与父子块、来源仍在存储中。查询先用小块定位，再按预算读取所需原文。

| 对象 | 职责 | 面试时避免混淆 |
|---|---|---|
| raw event | 宿主记录的原始事件 | 当前提示词只是事件投影 |
| Parent / Child | 原文块与定位视图 | Parent 目标大小不是无限预算 |
| Surface | 当前模型可见消息 | detached 是驻留变化 |
| Ledger | 分层记录、引用、状态、日志 | 保存与成功召回是两件事 |
| sourceRefs | session/seq 来源入口 | ID 本身不是证据正文 |

历史配置 65% 触发、35% 目标、80% 原生压缩兜底；首先确认分母是该次有效输入额度。固定 system/tools/当前输入也占空间。32000 等口头近似不能替代实际 32768 总窗口与 2048 输出上限 配置。

**追问入口：**五类对象 C09；压力 C10；未结束工具与超大事务 C11；Child/Parent C12；事实更新 C13；E5 状态 C14；作用域 C15；trace 和四层成熟度 C16。

### 速查 4｜实习与个人贡献

**最新口述：**我在华为担任通用软件开发实习生，负责下一代 NPU 架构预研中的组件仿真链路打通与仿真加速机制设计、实现及运行验证。完成 75 个未通过代码门禁样例的定位、修复、回归验证与代码提交，涉及内核 panic 和进程虚拟地址访问错误。自研检索工具帮助我理解代码仓和定位入口，我负责判断原因、实现修改及验证，并沉淀十余份分析文档。

### 速查 5｜三组实验卡片

| 实验 | 比较身份 | 结果与口径 |
|---|---|---|
| Flask | 常驻 CKB / 预设关键词 grep | 文件 Recall@8 100%/100%；符号 40%/100% |
| LongMemEval-S 40 题子集 | OpenViking+DSH / 完整插件+DSH | 40题中答对21题 -> 40题中答对27题，0.525 -> 0.675 |
| 同题去 E5 | 仅词法 / E5 完整方法 | 40题中答对25题 -> 40题中答对27题，0.625 -> 0.675 |

**DSH 固定条件：**相同 DeepSeek 模型、原生压缩、32K 总窗口、2K 输出上限；确定性关键词/包含判分器。LongMemEval-S 五类各 8 题。NoLiMa 20 单跳+20 双跳、reasoning=off、每题最多一次 recall/open，属于另一个协议。

**开销读法：**每题先取主请求可见 token 峰值，再求均值，20170 -> 16118，降低20.1%；回答链 Provider 输入输出合计1195991 -> 878282，降低26.6%。两项分母、聚合和用途不同，不能相加。外部记忆抽取、embedding、内存和延迟另外计量。

**必须保留的反向信息：**CKB 符号召回低于 grep；DSH 在多会话、时间推理两类中各少答对一题；去 E5 与完整版本存在双向胜负。过去40题中答对26题实验与本次40题中答对27题保留不同身份。

## 第二部分：共同核心 - CKB 完整学习单元


<a id="C01"></a>
### C01 怎样讲项目与本人贡献

**考察：**能否区分需求、个人动作和第三方能力。

**30 秒口述：**CKB 负责代码入口，DSH 负责会话历史。我设计和实现的是来源组织、预算检索与运行时编排，并用各自固定实验观察结果。华为实习提供了真实代码理解、修改和运行验证场景。

**2 分钟展开：**
1. 从陌生代码和有限窗口出发，各用一句话讲问题。
2. 指出自己组织的数据、接口和验证；给出组件输入输出。
3. Tree-sitter/LSP/SQLite、DSH Hook/E5 分别归第三方基础能力。
4. 用一组独立结果结束，联合接入另列设计题。

**例子：**教学表达练习：把“我做了AI平台”改成“我设计查询入口，把任务转换为来源绑定的源码范围，并测量召回与上下文”。

**连续追问：**
- 追问本人做什么？讲接口、数据约束、实现和验证动作。
- 为什么不用现成搜索？说明自然语言入口与来源组织；同时承认 grep 对已知符号有优势。
- 两系统已联调吗？分别展示实验，联合图标为 B01 设计练习。

**常见错误：**把集成E5说成训练模型；把原论文全体结果归为个人全部实现。

**自测：**脱稿90秒，并让听者指出每项动作的主语。

**来源：**原稿§2、18；最新简历；E01/E02。来源身份见[证据附录](E:/knowledge_builder/self-workspace/knowledge-base/human/analysis/秋招学习证据索引与原题映射%20v2.md#sources)。


<a id="C02"></a>
### C02 固定版本、overlay 与 staging

**考察：**变化发生时如何解释旧知识。

**30 秒口述：**固定提交让解析和解释指向同一份代码。活动修改单独记录到 overlay，新提交在 staging 构建和核验后再切换，所以旧结论和新变化能区分。

**2 分钟展开：**
1. commit固定仓库；blob固定文件字节；path/range定位声明。
2. 用户未提交改动与基线对比，避免把新行号解释成旧行号。
3. staging复用相同blob，变化文件重新解析/审阅。
4. 通过索引与来源核验后切换，旧基线可追溯。

**例子：**教学：提交A中函数在20行，工作树插入5行。展示A:20与overlay:+5，而非把A证据贴到当前25行后宣称已复核。

**连续追问：**
- 同路径同语言够不够？还需内容blob和旧解析状态。
- staged通过但有新改动？重新比较绑定，切换前确认候选对应的版本。
- 旧链接怎么打开？区分固定快照入口与当前工作树入口。

**常见错误：**把mtime当成Git事实身份；将staging候选直接称为已发布。

**自测：**画A基线、工作树差异、B候选三格，标出读取/写入关系。

**来源：**原稿CKB-Q11-Q14；E03。来源身份见[证据附录](E:/knowledge_builder/self-workspace/knowledge-base/human/analysis/秋招学习证据索引与原题映射%20v2.md#sources)。


<a id="C03"></a>
### C03 Tree-sitter 与 LSP 的证据如何融合

**考察：**结构范围和语义来源是否混淆。

**30 秒口述：**语法解析给出文件、类、函数与范围，语言服务器补定义、引用和符号。融合时保留提供器、范围及状态，冲突需要回到对应版本源码核查，合法空结果仍是有意义的协议结果。

**2 分钟展开：**
1. 对齐文件URI、位置编码、声明范围和限定名，保留来源。
2. Tree-sitter结构是入口，LSP补充语义关系。
3. 区分成功且为空、部分结果、超时、协议失败和阻断诊断。
4. 原材料给出适配与审阅流程；本次不虚构统一匹配公式。

**例子：**教学：一个只包含导入的文件返回空documentSymbol，不能推断服务坏了；同名foo分别在两个命名空间，不能仅凭name合并。

**连续追问：**
- 行范围不同怎么办？检查文件版本、位置编码和包含关系，再读源码。
- 动态调用能全解析吗？标注提供器精度，不将未检出当不存在。
- 如何测？空文件、同名符号、中文前缀位置、超时分别造fixture。

**常见错误：**把AST结构等同于全部动态调用图；把合法空结果当错误。

**自测：**给5种提供器返回写状态表：[]、partial、timeout、malformed、fatal diagnostic。

**来源：**原稿CKB-Q7-Q16；原CKB手册LSP节；E03；通用LSP协议入口见附录。来源身份见[证据附录](E:/knowledge_builder/self-workspace/knowledge-base/human/analysis/秋招学习证据索引与原题映射%20v2.md#sources)。


<a id="C04"></a>
### C04 facts、SQLite 与中文导航怎样更新

**考察：**保存、检索与阅读层的责任。

**30 秒口述：**facts保存来源事实，SQLite组织完整实体、章节和关系，中文页面负责阅读和跳到源码。页面少不等于机器事实少；一致性核验要检查来源、索引和投影的对应关系。

**2 分钟展开：**
1. 固定版本解析与Agent来源复核产生可追溯事实。
2. facts/graph提供重建基础；机器库生成实体、章节、来源与全文索引。
3. 中文导航按所有权和配额投影，独立记录回链知识页。
4. 更新验证覆盖索引完整性、链接、镜像和保留人工内容；跨文件步骤不是一个SQL事务。

**例子：**教学：函数被归为某页附录，仍应通过实体ID在SQLite中找到。删除一个人工笔记不能用重新生成机器页来“修复”。

**连续追问：**
- 为什么不直接检索所有Markdown？机器层保留完整结构与稳定来源。
- SQLite提交了但页面写失败？候选状态不能宣布全体完成，重放对应生成步骤。
- 作者归属？脚本决定结构配额，Agent复核职责文字。

**常见错误：**把人类页数量当实体覆盖率；手改生成器管理文件绕过来源更新。

**自测：**用“新增函数”列出facts、SQLite、中文页各自变化及一次失败恢复点。

**来源：**原稿§3、7、9、CKB-Q17-Q24；E03。来源身份见[证据附录](E:/knowledge_builder/self-workspace/knowledge-base/human/analysis/秋招学习证据索引与原题映射%20v2.md#sources)。


<a id="C05"></a>
### C05 fast 与 precise 的实际检索步骤

**考察：**候选边界、排序与停止条件。

**30 秒口述：**fast先用词项和FTS5找种子，再做有界两跳传播；precise增加源码全文并执行固定轮次加权PageRank。两者都稳定排序、限制物化候选，并在预算内返回结果。

**2 分钟展开：**

### C09 raw、Parent、Child、Surface、Ledger

**考察：**能否区分原文、索引与可见投影。

### C10 65%、35%、80%怎样配合

**考察：**分母、固定开销与触发顺序。

**30 秒口述：**先按这次模型窗口和输出预留确定有效输入额度，再看Surface压力。插件65%触发、向35%目标压缩；system、tools和当前输入形成固定部分，压不下去时由DSH原生压缩按其80%设置兜底。

### C11 工具未返回和超大事务怎么处理

**考察：**结构完整性的三个层级。

### C15 会话作用域、异步顺序与重放

**考察：**并发与持久化责任。

**30 秒口述：**会话记忆按session限定，异步写入按scope队列排序，日志记录状态变化。重放要识别重复事件，并在等待返回后重新检查记录；“单线程Node”并不消除异步交错。

**2 分钟展开：**
1. key包含scopeKind/scopeId/id，跨workspace访问要额外授权。
2. append-only journal保留事件顺序，快照只是加速恢复。
3. 重试与重放按eventId去重，冲突payload要报错。
4. 外部动作成功但日志未落盘属于不确定窗口，状态查询或幂等键解决，不能仅靠本地重放证明恰好一次。

**例子：**教学：s1与s2都有P1；只用P1作缓存键会串内容。EX04在更新2次后重放重复事件，状态应该保持而非再加一次。

**连续追问：**

### C18 基础如何连接到项目

**考察：**能否用基础概念解释故障与设计。

**30 秒口述：**我从资源所有权、进程边界和状态更新解释工程行为。C++资源由对象生命周期管理，异步任务要处理交错；SQLite事务与索引更新解决局部一致性，跨文件和外部动作仍需自己的恢复流程。

**2 分钟展开：**

**连续追问：**
- shared_ptr线程安全意味着对象线程安全吗？引用计数与对象内部共享状态是两回事。
- async为何还卡？CPU循环未让出执行。
- WAL就没锁？写竞争与busy仍需要处理。

**常见错误：**把进程隔离当数据安全自动完成；把本地事务当多文件原子发布。

### P1｜相关基础短读

- **虚拟内存：**虚拟地址由映射与权限决定可访问性。进程非法访问与内核panic是现象层级，根因可能涉及生命周期、权限或状态；先看在哪个阶段、谁访问什么，再用证据排除。
- **锁与异步：**互斥锁保护共享状态，统一锁顺序降低死锁机会；异步await期间状态可改变，因此补齐后重读。超时只说明等待结束。
- **索引与事务：**索引用空间/写入成本换查询定位；事务保证其覆盖范围内的一致状态。机器索引和Markdown发布仍要额外步骤。
- **评测：**Precision=TP/(TP+FP)，Recall=TP/(TP+FN)，空分母必须明确策略；P95的计算方法与样本规模一起报告。
- **科研方法：**MCTS是搜索与模拟决策；队友建模、POMDP与数字孪生帮助解释状态不完全可见和对照实验。本人贡献以原稿为准，算法推导和论文细节待全文支持。

**常见错误：**全局lastQuery导致串会话；把异步回调次序当提交顺序。

**自测：**设计两会话交错时序，写出每个回调的目标state。

**来源：**通用设计；C15；DSH已有scope机制E10。来源身份见[证据附录](E:/knowledge_builder/self-workspace/knowledge-base/human/analysis/秋招学习证据索引与原题映射%20v2.md#sources)。


<a id="B04"></a>
### B04 超时、重试、取消和不确定结果

**考察：**能否防止重复副作用。

**30 秒口述：**超时意味着调用方没拿到结果，不代表动作没执行。读取操作可按策略重试；有副作用的修改先查结果或用幂等键。取消通过状态和信号传播，还要处理迟到响应。

**2 分钟展开：**
1. 请求统一截止时间，分配每步剩余预算。
2. 临时失败限次退避，参数错误直接返回。
3. apply用requestId+expected_blob，重复请求返回相同结果。
4. timeout之后标unknown，查补丁/文件状态；取消不伪造回滚成功。

**例子：**教学：写文件完成后连接断开。盲重试追加一遍内容会重复，先比较预期hash与实际修改。

**连续追问：**
- 可重试错误有哪些？网络临时失败与限流候选，权限/参数通常需改变请求。
- sidecar超时？还应检查进程和编码状态。
- 恰好一次？跨系统需持久幂等和对账，不能靠一句队列保证。

**常见错误：**所有异常一律重试；取消标志等同于子进程结束。

**自测：**EX04解释“动作已发生但确认丢失”的恢复路径。

**来源：**教学设计；原稿CS-Q21/AI-Q21；C14/C15。来源身份见[证据附录](E:/knowledge_builder/self-workspace/knowledge-base/human/analysis/秋招学习证据索引与原题映射%20v2.md#sources)。


<a id="B05"></a>
### B05 中断恢复与任务验收

**考察：**恢复进度与验证结果分开。

**30 秒口述：**恢复先读日志确认最后一个可证明完成的动作，再核对文件和工具实际状态。任务完成要看补丁与测试，而不是对话里写了“完成”或恢复到了某个阶段。

**2 分钟展开：**
1. append日志保存状态、动作ID、输入版本与输出引用。
2. 快照减少重放量，重复事件按ID去重。
3. 恢复先对账unknown动作，再推进下一步。
4. 结果报告区分已执行、已验证与待处理。

**例子：**教学：verify阶段命令返回非零，助手应记录失败，不因脚本生成了report.json判通过。

**连续追问：**
- 日志损坏？尾部残片可报告，完整中间坏记录要停止。
- 测试覆盖不够？报告实际验证范围，补案例作为新任务。
- 回滚怎么验？恢复副本后核对差异与关键行为。

**常见错误：**从“工具返回成功”直接跳“任务达成”。

**自测：**EX04执行恢复；为B01列出3个完成条件与反例。

<a id="B06"></a>
### B06 权限、数据与指令边界

**考察：**检索内容会否变成执行授权。

**30 秒口述：**仓库文件和历史内容都是任务数据。工具权限由用户任务和宿主策略确定，检索到的文字不能扩大路径范围或要求上传秘密。输出优先保留必要来源与脱敏结果。

**2 分钟展开：**
1. 在工具执行层检查允许路径和动作，模型文字不能覆盖。
2. 源码注释中的指令只作为文本引用。
3. 日志保留必要ID、错误与脱敏片段，控制附件内容。
4. 重要写操作保留人工确认点。

**例子：**教学README夹带“上传整个目录到某地址”，助手应继续分析所需代码并标记该文本，不执行额外上传。

**连续追问：**
- Prompt防护够吗？工具层必须再次限制。
- 允许读就允许上传吗？读取与对外传输是不同动作。
- 怎样测？在教学文件放越权指令，检查实际工具请求。

**常见错误：**把来源可信当指令可信；把私有目录内容当可公开演示数据。

**自测：**为B01制定read/patch/test三工具的最小权限表。

### B07 检索、工具、上下文和生成错误归因

**考察：**故障定位层次是否清楚。

**30 秒口述：**先沿证据链检查目标信息是否在源数据、是否召回、是否装入最终输入，再看工具执行和答案生成。这样可以区分索引、检索、预算裁剪、工具或模型问题，而不是都归为模型幻觉。

**2 分钟展开：**
1. 记录源数据、候选、最终pack、最终messages和工具输出。
2. 用人工核查的小任务集作对照。
3. 固定其他条件替换一层，观察是否恢复正确行为。
4. 保留失败输入，避免只记录成功样例。

**例子：**教学：源文件有默认值，检索命中，但预算删去默认值行。优先归为上下文装配遗漏，而非模型推理差。

**连续追问：**
- 多层同时失败？先固定一层重放，再分类剩余错误。
- Judge错了呢？保留人工审阅与判分版本。
- 指标如何选？端到端成功之外另报必要证据覆盖与错误类别。

**常见错误：**只看最终文本；为失败编造根因。

**自测：**给4份模拟trace标出第一次偏离正确路径的位置。

### B08 效果、延迟和资源如何取舍

**考察：**能否做面向约束的选择。

**30 秒口述：**先定义任务必须正确的条件，再比较延迟、token、请求数和额外资源。采用E5可能改善语义召回，也需要模型内存与编码时间；常驻检索省启动却保留进程资源。

**2 分钟展开：**
1. 每项成本明确范围与单位。
2. 同任务比较轻量词法与E5配置，报告失败和超时。
3. 预算优先保证必要证据，缺口才追加调用。
4. 用满足最低质量的方案比较成本，避免只最小化tokens。

**例子：**教学：方案一0.67分用1M回答token，方案二0.65分用0.6M；是否选二取决于质量门与错误严重度，不由单指标自动决定。

**连续追问：**
- 两项token降幅可加吗？分母不同不能加。
- 低延迟但高错误？先检查质量门。
- 什么叫总成本？还要计构建、embedding、CPU/GPU/内存和人工。

**常见错误：**将DSH26.6%说成所有付费成本；拿不同数据集得分直接比。

**自测：**EX05算分项指标，给出带质量门的选择理由。

## 第四部分：Agent 游戏测试专项


<a id="A01"></a>
### A01 使用Agent测游戏，与测试Agent

**考察：**被测对象与成功定义。

**30 秒口述：**用Agent测游戏时，游戏状态和需求决定是否有缺陷；评估Agent时，看它是否选择有效步骤、准确判断并保存可复现证据。游戏测试失败而Agent成功是可能的，因为它正确发现了缺陷。

**2 分钟展开：**
1. 游戏质量表：预期奖励、状态转换、失败恢复。
2. Agent质量表：动作合法、等待条件正确、判断准确、证据完整。
3. 执行器、环境、模型和游戏分别归因。
4. 同一运行可产出两张评分表。

**例子：**教学：奖励实际加了两次，Agent依据服务状态报告重复发奖。游戏失败、Agent发现任务通过；若Agent只看动画猜测则证据不足。

**连续追问：**
- Agent没找到bug是否游戏通过？只能说明该执行路径未发现。
- 执行器点错怎么记？执行器失败，避免记游戏bug。
- 谁是oracle？独立规则或状态，不是Agent自己说了算。

**常见错误：**用“通过率”一个词混用游戏与Agent结果。

**自测：**把一次教学运行同时填写game_verdict和agent_verdict。

**来源：**新增岗位教学；G场景与EX06。来源身份见[证据附录](E:/knowledge_builder/self-workspace/knowledge-base/human/analysis/秋招学习证据索引与原题映射%20v2.md#sources)。


<a id="A02"></a>
### A02 从奖励领取需求到测试判据

**考察：**状态机和独立预期。

**30 秒口述：**先明确奖励资格、领取次数、余额变化和重试行为，再写正常、边界和异常测试。用可查询状态与奖励流水判定，不仅观察UI动画。

**2 分钟展开：**
1. 初态ready=false,claimed=false,balance=0；资格成立后可领10。
2. 相同reward在一个周期至多一次，重复requestId返回原结果。
3. 断开重连后状态持久且余额不重复变化。
4. 本地教学状态机充当oracle，商业游戏接口另需真实授权。

**例子：**教学完整场景G：周期day1，用户u1先未达成任务，claim应拒绝且余额0；达成后claim(k1)余额10；重放k1、换k2再领都不能到20。

**连续追问：**
- 新周期呢？rewardKey含周期，不能永远禁止再领。
- UI成功但余额0？核查权威状态和延迟，先分类不一致。
- 要测什么边界？未就绪、已领取、重复、断线、重启。

**常见错误：**只写“领取成功”；把动画当余额事实。

**自测：**EX06列出五类输入和预期；G为教学，非个人游戏项目。

<a id="A03"></a>
### A03 观察、执行、等待与状态判定

**考察：**避免固定sleep和误点污染。

**30 秒口述：**动作执行前确认场景与目标，执行后等待明确状态变化或截止时间，再读取结果。观察过期、目标未出现和超时分别记录，不继续凭旧坐标操作。

**2 分钟展开：**
1. observation含stateVersion和可操作目标。
2. 执行器校验前置状态，再执行一动作。
3. 等待条件是奖励状态/流水出现，设置deadline。
4. 超时保留初态、动作和最后观测，不补造成功。

**例子：**教学G：点击后loading，固定100ms截图可能仍未到账；应等claim终态或超时，晚到结果另对账。

**连续追问：**
- 网络慢与bug如何分？记录耗时和环境，对照权威状态重放。
- 页面切换怎么办？重新观察后定位。
- GUI尚无实现？写设计与接口，不称已有自动化能力。

**常见错误：**固定sleep后无条件断言；复用过期目标位置。

**自测：**给G增加await_state(predicate,deadline)伪接口及超时分支。

<a id="A04"></a>
### A04 失败归因：游戏、环境、执行器、模型

**考察：**问题定位是否证据驱动。

**30 秒口述：**按链路逐层对账：初态和环境是否成立、操作是否实际执行、游戏状态是否违反规则、Agent判断是否与证据一致。保留unknown类别，避免缺证据时硬分。

**2 分钟展开：**
1. 环境：版本、网络、进程和测试数据。
2. 执行器：操作目标、返回、动作记录。
3. 游戏：余额/流水/状态是否违反oracle。
4. 模型：对相同证据的结论是否准确。

**例子：**教学G：点击未落到按钮且无服务请求，属于执行器问题；请求成功而同周期余额20，属于游戏状态违规候选；余额10而Agent称双领，属于判断误报。

**连续追问：**
- 为什么是候选？要先排除预期规则不同和测试数据污染。
- 两层都有错？记录主因与伴随问题，分开修复。
- 如何复现？固定初态与动作序列而非只留截图。

**常见错误：**由错误提示文字直接断定根因。

**自测：**写一份证据最小集合：version/initial/actions/state/decision。

**来源：**新增设计题；C17方法迁移，不代表已有游戏实习。来源身份见[证据附录](E:/knowledge_builder/self-workspace/knowledge-base/human/analysis/秋招学习证据索引与原题映射%20v2.md#sources)。


<a id="A05"></a>
### A05 复现、缩短路径、去重与回归

**考察：**缺陷报告能否供别人验证。

**30 秒口述：**报告需要固定版本、初态、最短可复现动作和预期/实际结果。先复现，再逐步删去无关操作；去重依据行为和根因证据，修复后复跑原路径及邻近边界。

**2 分钟展开：**
1. 保留原失败种子与完整路径。
2. 缩短时每次从同初态重置，删步骤后仍触发才保留。
3. 按错误类别、状态差异和条件聚类，根因未确认不强行合并。
4. 回归包含原用例、重复请求和新周期。

**例子：**教学G：move,open,ready,claim,close,claim出现双领；在本地状态机可缩为ready,claim,claim。真实GUI中open可能是必要前置，不能照搬删掉。

**连续追问：**
- 非确定性失败？保留seed与重复次数，报告复现频率。
- 相同panic栈是同bug吗？仍需条件与根因证据。
- 75样例怎样关联？样例可多对一根因，另建映射。

**常见错误：**仅凭截图相似去重；回归只跑修复后一次正常路径。

**自测：**EX06保留完整fail JSON，并手工删除无关步骤。

**来源：**教学G；用户75样例事实用于统计区别。来源身份见[证据附录](E:/knowledge_builder/self-workspace/knowledge-base/human/analysis/秋招学习证据索引与原题映射%20v2.md#sources)。


<a id="A06"></a>
### A06 误报、漏报、覆盖与成本

**考察：**分母是否正确、漏检能否估计。

**30 秒口述：**Agent报告缺陷后要与人工或规则标签对照算误报；漏报需要已知真值任务集。覆盖描述状态、转换和边界，不能用动作数代替；同时报告时间与请求开销。

**2 分钟展开：**
1. TP为确有缺陷且报告，FP为无缺陷却报告，FN为有缺陷却漏掉。
2. Precision/Recall分开；空分母明确undefined。
3. 定义状态/转换覆盖和需求条件覆盖。
4. 用标注的教学变体估计漏报，真实未知缺陷总数不能凭空填。

**例子：**教学：10个带缺陷样例检测8个，10个正常样例误报2个；precision=.8、recall=.8。若只知道8个报告，无法推漏报。

**连续追问：**
- 100%覆盖就无缺陷？只覆盖所定义模型的点。
- 怎么计执行成本？wall time、动作、模型/工具请求分别记录。
- 不同严重度呢？分层报告，不能全被平均掩盖。

**常见错误：**将报告数当真缺陷总数；覆盖率宣称所有游戏功能。

**自测：**EX05计算混淆矩阵，说明哪些数据足够算recall。

**来源：**新增教学评测；G；EX05。来源身份见[证据附录](E:/knowledge_builder/self-workspace/knowledge-base/human/analysis/秋招学习证据索引与原题映射%20v2.md#sources)。


<a id="A07"></a>
### A07 怎样测试Agent判定器

**考察：**被测Agent与评分器保持独立。

**30 秒口述：**先固定任务和判据，保存Agent原始动作与结论，再用规则或人工核对。模型裁判也可能错，需抽样人工复核和版本管理，不能把“裁判同意”当事实真值。

**2 分钟展开：**
1. G用状态规则判余额；自然语言解释用明确rubric。
2. 评分输入隐藏模型名称，保留裁判版本。
3. 记录自动/人工分歧，错误样本加入回归。
4. 被测Agent不能修改标签或评分配置。

**例子：**教学：Agent说“未重复发奖”而状态balance20，规则应判错，即使语言流畅。

**连续追问：**
- LLM裁判适合什么？开放解释可辅助，确定状态用规则。
- 判据变更怎么办？升版本，重算相关历史结果。
- 人工也分歧？先澄清需求和仲裁规则。

**常见错误：**用答案长度给高分；Agent自己给自己评估通过。

**自测：**给G输出写最小rubric：事实正确、证据引用、复现可用各0-2。

**来源：**新增教学；原稿AI-Q16；X2判分边界。来源身份见[证据附录](E:/knowledge_builder/self-workspace/knowledge-base/human/analysis/秋招学习证据索引与原题映射%20v2.md#sources)。

### A08 非确定性与隔离评测怎么做

**考察：**运行差异与选择性汇报。

**30 秒口述：**固定模型配置、提示词、工具和初始数据，重复运行保留每次结果。会话与记忆隔离避免上一题泄漏；异常退出也作为结果记录，不能只取最好一次。

**2 分钟展开：**
1. 定义任务ID、runID、seed、模型与提示词版本。
2. 相同题跨方法配对，固定资源上限。
3. 报完成率、任务成功、误报漏报、恢复耗时和token。
4. 模型随机性与环境波动分别分析；统计量须有真实重复数据。

**例子：**教学G：一轮超时、一轮正确、一轮误报，要保存三行；“只看成功那轮”会扭曲质量与成本。

**连续追问：**
- temperature=0绝对确定吗？仍需看服务、工具与调度变化。
- 环境隔离到哪？每题存储/会话/初态，共享服务是否带缓存另记。
- 失败重试？先定规则，原失败和重试都保留。

**常见错误：**把配置相同写成统计显著；删除异常样本再称100%完成。

**自测：**设计3次运行记录表，所有结果填写status与cost而非空白丢弃。

**来源：**新增教学；E12隔离实验作为方法参考。来源身份见[证据附录](E:/knowledge_builder/self-workspace/knowledge-base/human/analysis/秋招学习证据索引与原题映射%20v2.md#sources)。

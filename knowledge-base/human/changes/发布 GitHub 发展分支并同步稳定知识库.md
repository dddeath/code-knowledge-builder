# 发布 GitHub 发展分支并同步稳定知识库

标签：#类型/变更

## 修改内容

项目已建立 GitHub 发展分支 `codex/development-knowledge-builder`。该分支同时提供当前集成源码、与源码提交 `c533dd7…` 对齐的稳定知识库、面向人类的 README、Git LFS 大文件和可执行回滚入口。

## 修改时间

2026 年 9 月 3 日。

## 修改原因

源码、知识记录和 Agent 协作过程需要在同一远程分支上持续演进，使新的开发会话能够先读取已有方案和实验结论，再开始修改，减少重复实现和相互冲突的功能扩张。

## 实现概述

发展分支从既有公开发布历史继续，不改写 `main`。源码目录保存集成仓库的精确 tracked 文件，知识库目录保存人类页面、机器索引、工作记录、参考资料和研究缺口；ZIP 与 SQLite 通过 Git LFS 发布。README 仍以“了解知识库、安装项目、解释自己的项目”三个任务帮助人类指挥 Agent。

## 关联特性

本次发布连接源码事实新鲜度、对话绑定管理 Agent、低版本协议迁移、常驻 stdio、PDF 资料吸收、人类页面模板、中文检索实验、Tag 导航实验、页面扩张实验和语义向量实验。Canvas 保持实验状态，等待人类试用反馈。

## 当前结果

远端发展分支能够在独立目录完整克隆并展开 Git LFS。当前生产检索和保守页面投影保持不变；页面扩张与语义向量实验的负结果已经随知识库发布，后续 Agent 可以直接检索这些结论和适用边界。

## 适用边界

该分支是继续开发和评审的协作入口，不替代 `main`，也不把实验原型声明为生产默认。发布包含固定源码快照和稳定知识记录，不包含模型缓存、虚拟环境、活动锁或本地凭据。

## 深入阅读

需要接管发布、核对目录或执行回滚时，从“deployment_plan”进入，让 Agent 只展开当前操作所需的源码与知识库位置。

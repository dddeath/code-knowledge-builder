<a id="EX01"></a>
### EX01 历史切分：工具调用配对（35分钟，规划估计）

**任务：**实现split_history(events,target)。每条事件含kind=text/call/result与非负tokens，call/result带唯一调用ID。返回chunks及pending_tail；每个chunk带oversized标志。

**约束：**同一输入会话；调用ID不重复；result只能对应尚未结束call。将直到pending集合为空的连续事件作为完整unit；按target装入多个完整unit。单unit超限独占一chunk并标记oversized，未完成尾部不封存。非法输入抛ValueError，不删除原事件。

- 正常：text2,call(a)2,result(a)2，target4。检查事件顺序与配对。
- 边界：call(a),call(b),result(b),result(a)，结果逆序但都完成；单unit大于target；空输入。
- 异常：孤立result、重复call ID、重复result、target=0、负tokens。
- 未完成：call(a),call(b),result(a)应全部留在pending_tail。

**自己完成：**starter/tasks.py函数及至少4条测试；说明O(n)扫描与输出空间。**完成标准：**原事件恰好出现一次、顺序不变、任何完成chunk无未配对call、尾部明确。

<a id="EX02"></a>
### EX02 稳定Top-K与有界传播（30分钟）

实现stable_topk(scores,k)及propagate(seeds,graph,depth=2,decay=.5)。图为有向邻接表，边权与种子有限非负；本题按路径贡献求和，每层乘decay，不是CKB真实公式。

- 正常：A=1，A->B权.8，B->C权.5，输出所有累计分数与Top-2。
- 边界：k=0、k大于节点数、无边、同分按ID字典序、A<->B环只扩depth层。
- 异常：k<0、NaN分数、负权、depth越界。

**自己完成：**实现稳定排序与逐层frontier，不用“visited一次即永远忽略”替代多路径求和。**完成标准：**同输入重复次序一致，环按深度停止，能说明排序O(n log n)和有界图传播成本。

<a id="EX03"></a>
### EX03 C++所有权与异步生命周期（30分钟）

查看starter/ownership.cpp：函数创建unique_ptr，再返回按引用捕获该局部变量的lambda。先分析生命周期，不执行未定义行为。

- 正常：函数返回后的任务仍能使用资源。
- 边界：任务移动后新owner可用，原owner不被错误解引用。
- 异常：资源创建后抛异常，也应恰好释放。

**自己完成：**使用移动捕获或合适所有权重新实现；增加alive计数断言，说明何时选择shared_ptr。**完成标准：**0->1->0生命周期、没有局部悬空引用、解释作用域释放。参考实现采用C++14；本机缺编译器，执行状态单独记录。

<a id="EX04"></a>
### EX04 日志重放、重复与中断（35分钟）

实现replay(text)，输入NDJSON追加日志，每条恰含seq、id、key、value。唯一事件seq递增；完全相同ID/记录重复可去重，同ID不同payload抛错。返回state、last_seq、discarded_tail。

- 正常：seq1设置port8080，seq2设置port9090，返回最新值。
- 边界：重复seq1记录、空日志、有效末行未换行。
- 异常：同ID内容冲突、不同ID倒序seq、中间JSON损坏、已换行的坏记录。
- 中断：最后一行JSON不完整且无换行，忽略该尾部并设置discarded_tail=true。

**自己完成：**区分重复、损坏和未提交尾部，拒绝静默吞掉中间坏行。**完成标准：**多次重放相同状态；解释这个本地模型不证明外部动作恰好一次。

<a id="EX05"></a>
### EX05 指标计算与口径（25分钟）

实现metrics(tp,fp,fn,latencies)和reduction(before,after)。Precision/Recall空分母返回None；空延迟P95=None，非空按线性插值。成本before>0，after>=0。

- 正常：TP8/FP2/FN2，延迟[1,2,3,4]；上下文11227.5->2294。
- 边界：全零混淆矩阵、一个延迟、空列表、after大于before（允许负降低率）。
- 异常：负计数、NaN延迟、before=0。
- 分析：40题中答对21题与40题中答对27题差多少题？每题峰值均值和所有请求token总和能否相加？

**自己完成：**代码及分母解释。**完成标准：**计算正确，单位与聚合明确，不使用四舍五入后的百分比继续做精确推断。

<a id="EX06"></a>
### EX06 奖励状态机、执行与失败证据（40分钟）

实现RewardGame与run_game。初态day1、ready=false、claimed=false、balance=0。ready后同周期最多加10；每次claim带request_id，同ID同周期返回首次结果，跨周期重用同ID报冲突。restart从snapshot恢复；新周期清ready/claimed，保留累计balance与请求记录。

- 正常：ready -> claim(k1)，余额10。
- 边界：未ready领取拒绝；同k1重放、换k2重复领；restart后重复领；day2重新ready可再加10。
- 异常：空ID、未知动作、跨周期重用ID、预期余额与实际不一致。

run_game逐步保存index、initial、action、result/error、actual、pass，遇失败停止并保留记录。动作可带expect_balance和expect_status。

**自己完成：**本地模型和执行器；用人工错误expect_balance=20生成可检查失败记录，再写正确判据。**完成标准：**同周期至多发一次、恢复后不重复发奖；游戏判据与Agent判断分开。这是教学状态机，不包含GUI或真实游戏接入。
